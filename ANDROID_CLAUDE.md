# Starlinkee Android — Context for Claude

This is an Android app (Kotlin + Jetpack Compose) that is a companion to the
**Starlinkee v2** Next.js web platform. The Android app's sole purpose is:

> A worker scans/selects a plate number → taps the phone to an NFC chip →
> the app atomically records the NFC UID in the backend database AND writes
> the correct URL to the chip. Internet connection is mandatory; no offline mode.

---

## Backend: Starlinkee v2 (Next.js + Supabase)

**Production URL:** `https://starlinkee.com` (or whatever is in `.env`)  
**Tech:** Next.js App Router, Supabase (PostgreSQL), deployed on Vercel

### What a "plate" is

Physical NFC/QR tiles sold to businesses. Each plate has:
- `plate_number` — 6-char uppercase code (e.g. `ABCDEF`), unique, printed on the tile
- `subscription_id` — which customer subscription it belongs to (nullable = unassigned)
- `secret_key` — internal key, not exposed to Android app
- `plate_language` — `en` / `de` / `pl`
- `number_of_visits` — incremented on each NFC tap by end user

When an end user taps the plate, their phone opens:
```
https://starlinkee.com/plate/{plate_number}
```
That URL is what gets written to the NFC chip NDEF record.

### Current `plates` table schema (Supabase PostgreSQL)
```sql
create table plates (
  plate_id         serial primary key,
  subscription_id  integer references subscriptions(subscription_id),  -- nullable = unassigned
  plate_number     varchar(6) not null unique,
  plate_language   text not null default 'en',
  number_of_visits integer not null default 0,
  secret_key       text not null,
  created_at       timestamptz not null default now(),
  updated_at       timestamptz not null default now()
);
```

**The Android app requires adding these columns** (migration must be applied to Supabase):
```sql
ALTER TABLE plates
  ADD COLUMN nfc_uid        text unique,          -- UID of the physical NFC chip
  ADD COLUMN nfc_assigned_at timestamptz,         -- when it was tagged
  ADD COLUMN nfc_assigned_by text;                -- which worker (from API key name)
```

## API: Endpoints the Android app uses

All endpoints live on the same Next.js backend. The app authenticates using
a static `X-Mobile-Key` header — a secret key generated in the admin panel
and stored in Android app settings (no OAuth, no sessions).

### 1. Verify a plate exists
```
GET /api/mobile/plates/{plate_number}
Headers: X-Mobile-Key: <key>

200 OK:
{
  "plate_number": "ABCDEF",
  "nfc_uid": null,            // null = chip not yet tagged
  "subscription_id": 42,      // null = plate unassigned to any customer
  "plate_language": "en"
}

404: plate does not exist
401: bad key
```

### 2. Assign NFC UID atomically
```
POST /api/mobile/plates/assign-nfc
Headers: X-Mobile-Key: <key>, Content-Type: application/json

Body:
{
  "plate_number": "ABCDEF",
  "nfc_uid": "04:A1:B2:C3:D4:E5:F6",
  "idempotency_key": "<uuid generated by app per attempt>"
}

200 OK:
{
  "nfc_url": "https://starlinkee.com/plate/ABCDEF"  // write this to the chip
}

409 Conflict: nfc_uid already assigned to a different plate
422: plate_number does not exist
401: bad key
```

The `idempotency_key` prevents double-writes if the network request succeeds
but the app crashes before writing to the chip — on retry the server returns
the same `nfc_url` without error.

## Android App: What to build

**Language:** Kotlin  
**UI:** Jetpack Compose  
**Min SDK:** 26 (Android 8.0) — NFC NDEF write requires API 19+, but 26 is safe minimum  
**NFC:** `android.nfc.NfcAdapter`, `NdefRecord.createUri()`, `NdefMessage`

### App flow (single screen is enough for MVP)

```
[Screen]
  - Text field: plate number (or QR scan button)
  - Status indicator: plate found / not found / already tagged
  - Big CTA button: "Tap NFC chip now" (enabled only when plate is valid)
  - Result: success / error

[On "Tap NFC" pressed]
  1. enableForegroundDispatch — Android will send NFC Intent to this activity
  2. User taps phone to chip
  3. onNewIntent fires with TAG extra

[On NFC Intent received]
  1. Check internet → if offline: show error, stop
  2. Read NFC UID from tag
  3. POST /api/mobile/plates/assign-nfc with idempotency_key = fresh UUID
  4. On 200 OK: write nfc_url to chip as NDEF URI record
  5. On write success: show green checkmark
  6. On any error: do NOT write to chip, show specific error
```

### Atomicity guarantee

The only source of truth is the database. Write order is:
1. **DB first** (POST assign-nfc)
2. **Chip second** (write NDEF)

If DB succeeds but chip write fails → worker retries with same `idempotency_key`
→ server returns same URL → chip gets written on second attempt.

If chip is written but DB failed → impossible by design (chip write only happens after 200 OK).

### NFC write snippet (reference)
```kotlin
fun writeNdefUrl(tag: Tag, url: String) {
    val ndefUri = NdefRecord.createUri(url)
    val ndefMessage = NdefMessage(arrayOf(ndefUri))
    val ndef = Ndef.get(tag) ?: throw IOException("Tag does not support NDEF")
    ndef.connect()
    try {
        ndef.writeNdefMessage(ndefMessage)
    } finally {
        ndef.close()
    }
}
```

### Network layer
Use **Retrofit** + **OkHttp**. Base URL comes from `BuildConfig.API_BASE_URL`
(set in `build.gradle` per build variant: debug points to local tunnel, release to prod).

### `AndroidManifest.xml` permissions needed
```xml
<uses-permission android:name="android.permission.NFC" />
<uses-permission android:name="android.permission.INTERNET" />
<uses-feature android:name="android.hardware.nfc" android:required="true" />
```

## Distribution (no Google Play Store needed)

This is an internal app for workers — skip the Play Store ($25 fee + review process).

**Recommended setup:**
```
GitHub Actions → build APK on every push → Firebase App Distribution →
workers get email notification → install / update with one tap
```

Firebase App Distribution is free. Add worker emails in the Firebase console;
they receive a link and install directly. Updates push automatically.

**One-time setup on each Android device:**
Enable "Install from unknown sources" in Android Settings → Apps → Special app access
(or prompted automatically on first install). Takes 3 taps.

**Alternatives if Firebase is overkill:**
- Send `.apk` via Telegram (no size limit) or WhatsApp (limit 100 MB, APK usually 5–15 MB)
- Upload to Google Drive and share link
- GitHub Releases (CI uploads APK as release asset, always-current download link)
